# robot-sim

フリッパー付きクローラロボットのシミュレータ。ラグを 1 つずつ剛体として計算し、ブロックの角にラグが引っかかって段差を越えるところまで再現する。物理エンジンから Rust で書いていて、外部クレートはゼロ。Python などのほかの言語も要らない。

- 実行ファイル `robot-sim.exe` を、設定ファイル(`key = value` の行)で動かす。
- ロボットは拡張 URDF で書くか、パラメータ(大きさ、質量、ラグの形など)から作る。サンプルは `robots/simple_crawler/simple_crawler.urdf`(寸法と質量を見本のために決めた架空のクローラ。20 kg、主クローラ 2 本とフリッパー 4 本)。
- 地形はブロックの高さの格子。名前と数値で指定する。サンプルのコースに、表せる地形を全部並べてある。
- 走らせた様子は記録(JSON)に取り、`viewer/viewer.html` であとから見る。
- 学習などに使うときは、Rust のライブラリ(`sim-task` の `World`)から何台も並べて動かせる。学習の課題とアルゴリズムは使う側が書く。

単位は m、kg、s、rad(設定ファイルの関節の角度だけは度)。座標は x が前、y が左、z が上。

## 必要なもの

- Windows 10 / 11(64 ビット)
- Rust(stable、MSVC)
- 記録を見るためのブラウザ(Edge、Chrome など)

## ビルド

```sh
cargo build --release                     # target/release/robot-sim.exe
```

`robot-sim.exe` は Windows に最初から入っている DLL だけを使う(C ランタイムも中に入れてある)。ほかの PC へは、exe とロボットのファイルと設定ファイルを持っていけば動く。

## はじめに

```sh
target\release\robot-sim.exe run examples\course.txt
```

サンプルのロボットが、決まった指令(ベルトは前へ 0.5 m/s、前のフリッパーを 40 度上げる)でサンプルのコースを走り、進み具合を表示して、記録 `examples/course_run.json` を書く。`viewer/viewer.html` をブラウザで開き、その記録をドロップすると再生できる。

コマンドを打たなくても動かせる:

- **`robot-sim.exe` をダブルクリックする**: ブラウザに操作の画面(GUI、下の「GUI」)が開く。
- **設定ファイルを `robot-sim.exe` のアイコンにドロップする**: その設定で `run` する。終わったら Enter を押すまで窓を閉じない(結果やエラーを読めるように)。

| コマンド | 動き |
|---|---|
| `robot-sim` | GUI を開く |
| `robot-sim run <設定ファイル>` | 設定のとおりにロボットを走らせ、記録を書く |
| `robot-sim info <ロボットのファイル>` | ロボットの名前、質量、関節、ベルト、モーターを JSON で表示する |
| `robot-sim urdf <パラメータ>` | パラメータから作ったロボットを、拡張 URDF で表示する(下の「パラメータからロボットを作る」) |

## GUI

`robot-sim.exe` を引数なしで起動する(ダブルクリックでもよい)と、ブラウザに操作の画面が開く。左で値を選び、右のビューアで見る。

- **ロボット**: パラメータ(下の「パラメータからロボットを作る」)をフォームで変える。サンプルに戻す、ファイル(パラメータか `.urdf`)を開く、パラメータを保存する、ができる。
- **地形**: 種類とキーを選ぶ。
- **走らせ方**: 摩擦、左右のベルトの速さ、関節の目標角度、最長の時間、指令の間隔。
- **プレビュー**: 値を変えると、ロボットが地形の始まりに立った様子がすぐに右に出る(形と地形を見ながら選べる)。
- **実行**: 「走らせる」で計算し、進み具合を表示する。終わると右で再生する。「記録を保存」で記録(JSON)を保存する。
- **手で操縦する(テレオペ)**: 「操縦を始める」で、今のロボットと地形のまま、キーボードで実時間に操縦する。寸法やラグを変えたロボットが越えられるかを、その場で試せる。進んだ距離、高さ、傾き(60 度を超えると赤)を表示し、終わったら操縦した記録を再生、保存できる。最長の時間(走らせ方)で止まる。画面を閉じるなど指令が 3 秒届かないと止まる。

  | キー | 動き |
  |---|---|
  | W、↑ / S、↓ | 前へ / 後ろへ(ベルトの速さは「ベルトの速さ」の欄) |
  | A、← / D、→ | 左へ / 右へ回る(片側のベルトを止める。前後のキーと一緒なら旋回しながら進む) |
  | R / F | 前のフリッパーを上げる / 下げる(「フリッパーを動かす速さ」の欄の速さで) |
  | T / G | 後ろのフリッパーを上げる / 下げる |

- **終了**: 画面の「終了」か、exe の窓を閉じる。

画面は、`robot-sim.exe` がこの PC の中だけ(127.0.0.1)で開く小さなサーバーが出す。起動のたびに作る合言葉(アドレスの `t=`)がない要求には答えない。ファイルを開く、保存するのはブラウザで、サーバーはファイルを読み書きしない。

## 設定ファイル

1 行に `key = value` を 1 つ。`#` から行末まではコメント。空の行は読み飛ばす。

書き間違いで黙って違う設定にならないように、`key = value` でない行、同じキーの 2 回目、値の間違い、知らないキーは、行番号付きのエラーになる。

`run` の設定(パスは設定ファイルの場所から数える):

| キー | 既定 | 意味 |
|---|---|---|
| `robot` | (必須) | ロボットのファイル(拡張 URDF か、ロボットのパラメータ) |
| `terrain` | `course` | 地形(下の「地形」) |
| `friction` | `0.8` | 地形の摩擦係数。ロボットの面の摩擦と小さい方が使われる |
| `seconds` | `90` | この時間で止める。地形の終わりを過ぎたら、その前でも止める |
| `belt` | `0.5, 0.5` | 左右のベルトの速度の指令 [m/s]。正で前進。モーターの力が足りなければ届かない |
| `joints` | 全部 `0` | 関節の目標角度 [度]。ロボットのファイルに書いた関節の順。サーボが関節の最大の速さと力で追う |
| `control_dt` | `0.05` | 指令を出す間隔 [s]。中では 1 ms の物理の計算をくり返す |
| `record` | (なし) | 記録を書くファイル。書かなければ記録しない |

ロボットは止まった状態で、車体の原点を `(0, 0, 平らな地面に置いた高さ)` に置き、+x を向いて始める。

## 地形

地形は、縦の柱を正方形のマスに並べたもの。柱の上面は水平か、マスごとに傾いた平面(同じ傾きのマスが並ぶと、継ぎ目のない 1 つの斜面になる)。名前と `key=value` で書く(書かないキーは既定)。

```
terrain = stairs rise=0.1 tread=0.3 steps=4
```

| 名前 | キー(既定) | 中身 |
|---|---|---|
| `flat` | | 平らな地面 |
| `step` | `h`(0.1) | 幅いっぱいの段差 1 つ。長さ 2 m |
| `curb` | `h`(0.1) | 左半分だけの段差。長さ 2 m |
| `rails` | `h`(0.05)、`every`(5) | 高さ `h` のレールを、0.1 m のマス `every` 個ごとに。長さ 4 m |
| `holes` | `h`(0.1)、`cell`(0.25) | 深さ `h` の穴の市松模様。長さ 4 m |
| `random` | `cell`(0.25)、`hmax`(0.2)、`seed`(0) | 高さが 0〜`hmax` のランダムなブロック。長さ 4 m。同じ `seed` なら同じ地形 |
| `stairs` | `rise`(0.08)、`tread`(0.25)、`steps`(8)、`skew_deg`(0) | 階段。`skew_deg` で段の縁を斜めにすると、片方のクローラが先に当たる |
| `slope` | `deg`(15) | 平らな地面から登る、なめらかな坂。長さ 3 m。登りきると、その高さの平らな地面が続く |
| `side_slope` | `deg`(15) | 左半分(y > 0)だけ、左へ登る横の坂。長さ 3 m。左のクローラだけが坂に乗る。坂の手前と奥の縁は、平らな地面との段差になる |
| `course` | `seed`(0) | サンプルのコース。rails、step、curb、holes、random(`hmax`=0.1)、stairs(4 段)、slope、side_slope をこの順に、間に 1 m の平らな地面をはさんで並べる。前の地形が終わった高さから次が始まるので、だんだん登る。全長 31 m |

- 地形は x = 1.2 m から前へ並び、幅は 3.5 m(y = 0 が中心)。
- 地形の手前は高さ 0、奥は最後の高さのまま、どちらも平らに続く。横は、端の列が前後の向きはそのまま、横へは端の高さのまま平らに続く。
- 地形の終わりから 0.6 m 先を過ぎると、`run` は止まる。
- 1 つのマスの上面は 1 つの平面なので、ねじれた面(前後にも左右にも高さが変わり、平面にならない面)は表せない。

## Rust から使う

`crates/sim-task` をライブラリとして使うと、何台も並べて、1 台ずつ違う指令で動かせる(学習の課題やアルゴリズムを自分で書くとき)。`robot-sim.exe` の中身(`crates/robot-sim/src/main.rs`)が短い使い方の例になっている。

| もの | 中身 |
|---|---|
| `robot::load(path)` | ロボットのファイル(拡張 URDF かパラメータ)を読む |
| `world::World::new(&model, 台数, スレッドの数, control_dt)` | 何台も並べた世界 |
| `set_terrain(選ぶ台, 地形, 摩擦)` | 選んだ台に地形を与える(選んだ台で 1 つを共有する) |
| `reset(選ぶ台, 位置, 向き, 関節の角度)` | 選んだ台を止まった状態で置き直す |
| `step(ベルト, 関節)` | 全台を `control_dt` 秒進める。ベルトは台ごとに左右 2 つ、関節は台ごとに関節の数だけ |
| `envs[k].state` | k 番の台の状態(姿勢、速度、角速度、関節、ベルト、時間) |
| `record(k)`、`stop_recording()`、`recording_json(記録)` | 記録を取る、止める、JSON にする |
| `terrain::TerrainSpec::parse(文字列)` と `build()` | 上の「地形」の書き方から地形を作る |
| `settings::Settings` | 上の「設定ファイル」の読み方 |

同じ入力、同じ PC、同じビルドなら、スレッドの数によらずビットまで同じ結果になる。計算は最後の 1 ビットに敏感なので、PC が違うと結果は少し変わる。

## 記録を見る

`viewer/viewer.html` をブラウザで開き、記録ファイルをドロップする(上のボタンで選んでもよい)。

| 操作 | 動き |
|---|---|
| ボタン、スペース | 再生と停止 |
| スライダー | 好きな時刻へ |
| ← → | 1 コマ戻る、進む |
| 速さ | 0.25〜4 倍 |
| ドラッグ、ホイール | 視点を回す、寄る(カメラは車体を追う) |

## パラメータからロボットを作る

拡張 URDF を書かなくても、数十個のパラメータ(設定ファイルと同じ `key = value`)からクローラを作れる。形は決まっていて、車体に主クローラが左右 2 本、フリッパーが 4 本(前後左右)。関節の位置、ベルトの間の板、フリッパーの重心などはパラメータから求めるので、どの値を変えても組み合わせが崩れない。

拡張子が `.urdf` でないロボットのファイルは、パラメータとして読む(設定の `robot`、`robot-sim info`)。`robot-sim urdf <パラメータ>` で、作られる拡張 URDF を表示する。書かなかったキーはサンプルの値になる(空のファイルはサンプルのクローラと同じ)。全部を書いた例は `robots/simple_crawler/simple_crawler.txt`(`simple_crawler.urdf` と同じロボットになる)。

| キー | サンプルの値 | 意味 |
|---|---|---|
| `name` | `simple_crawler` | ロボットの名前(英数字、`_`、`-`) |
| `chassis_mass`、`chassis_inertia` | 16、0.17, 0.45, 0.55 | 車体の質量 [kg] と慣性モーメント ixx, iyy, izz [kg·m²]。重心は主プーリーの軸の真ん中 |
| `chassis_friction` | 0.3 | 車体の摩擦 |
| `main_spacing`、`main_radius` | 0.5、0.06 | 主クローラの前後のプーリーの間隔と半径 [m] |
| `main_belt`、`main_belt_mass` | 0.04, 0.14、1.0 | 主クローラのベルトの、中心面から内端と外端までの距離 [m]、ベルトの質量 [kg] |
| `main_lugs` | 16 | 主クローラのラグの数。0 でラグなし(滑らかなベルト) |
| `main_lug_shape` | `rect` | ラグの形: `rect`(長方形)、`trapezoid`(台形)、`ramp`(上面を内側へ下げた長方形) |
| `main_lug_height`、`main_lug_length` | 0.015、0.03 | ラグの高さと、根元のベルトに沿った長さ [m] |
| `main_lug_top` | (根元と同じ) | `trapezoid` のときだけ: 先端の長さ [m] |
| `main_lug_ramp` | (なし) | `ramp` のときだけ: 下げ始める中心面からの距離と、内端の高さ [m](`<ramp from inner_height>`) |
| `flipper_length`、`flipper_radius` | 0.24、0.06 | フリッパーの長さ(関節から先のプーリーまで)とプーリーの半径 [m] |
| `flipper_belt`、`flipper_belt_mass` | 0.145, 0.185、0.5 | フリッパーのベルトの内端と外端 [m](主クローラの外側)、質量 [kg] |
| `flipper_mass`、`flipper_inertia` | 1、0.001, 0.006, 0.006 | フリッパー 1 本の質量と慣性モーメント。重心はフリッパーの真ん中 |
| `flipper_lugs`、`flipper_lug_*` | 10、主クローラと同じ | フリッパーのラグ。キーは主クローラの `main_` を `flipper_` にしたもの |
| `joint_range` | -1.57, 1.57 | フリッパーの角度の範囲 [rad]。正で先端が上がる |
| `joint_velocity`、`joint_effort` | 1.5、60 | 関節の最大の速さ [rad/s] と力 [N·m] |
| `servo_gain` | 4 | 関節のサーボのゲイン |
| `drive_torque` | 30 | モーターの最大トルク [N·m]。1 つのモーターが片側の 3 本のベルトを回す |

知らないキー、その形で使わないキー(`rect` のときの `main_lug_top` など)、重なるベルトはエラーになる。

## ロボットの書き方(拡張 URDF)

URDF に、クローラの要素を足した XML のファイル。全体の例は `robots/simple_crawler/simple_crawler.urdf`。

書き間違いでロボットが黙って変わらないように、読めない書き方は行番号付きのエラーになる: 知らない要素と属性、1 つしか書けない要素が 2 つ以上あるもの、計算しないもの(`<dynamics>`、`<mimic>`、箱以外の `<collision>` など)。`<visual>`、`<material>`、`<gazebo>`、`<transmission>` は読み飛ばす(CAD から書き出した URDF をそのまま使える)。

### 普通の URDF の部分

| 要素 | 読むもの | 制限 |
|---|---|---|
| `<link>` | `<inertial>`(`<origin xyz>`、`<mass value>`、`<inertia>`)、`<collision>` の `<geometry><box size>` と `<origin xyz>` | 慣性の非対角成分は使わない。`<collision>` は回転なしの箱だけ |
| `<joint>` | `type="revolute"`、`<parent link>`、`<child link>`、`<origin xyz>`、`<axis xyz>`、`<limit lower upper velocity effort>` | 回転関節だけで、親は根のリンク。軸は y 方向。原点の回転(`rpy`)は 0 だけ |

根のリンク(どの関節の子でもないリンク、1 つだけ)が車体になる。車体と関節の子リンク(フリッパー)は 1 つの剛体として動き、重心と慣性は関節の角度から毎ステップ求め直す。子リンクの座標は、関節の軸が原点で、角度 0 のとき車体と同じ向き。関節の順(ファイルに書いた順)が、設定ファイルの `joints` と `World::step` の関節の順になる。

### クローラの要素(`<robot>` の直下)

```xml
<track name="left_main" side="left" link="base_link">
  <pulley xyz="-0.25 0 0" radius="0.06"/>
  <pulley xyz="0.25 0 0" radius="0.06"/>
  <belt inner="0.04" outer="0.14" mass="1.0"/>
  <lugs count="16" spacing="even" inner="0.04" outer="0.14">
    <profile points="-0.015 0  0.015 0  0.015 0.015  -0.015 0.015"/>
  </lugs>
</track>
<drive name="left" max_torque="30" tracks="left_main left_front_flipper left_rear_flipper"/>
<plate track="left_main" y="0.14 0.145" inset="0.005"/>
<servo joint="front_left" gain="4"/>
<surface link="base_link" friction="0.3"/>
```

| 要素、属性 | 意味 |
|---|---|
| `<track name side link>` | クローラ 1 本。`side` は `left` か `right`(右は y が負の側)。`link` は根のリンクかフリッパーのリンク |
| `<pulley xyz radius>` | ちょうど 2 個。リンク座標での軸の位置(x と z)と、ベルト面の半径(2 個で同じ) |
| `<belt inner outer mass>` | 中心面からベルトの内端と外端までの距離、ベルトと一緒に動く質量 |
| `<lugs count spacing inner outer>` | ラグ。1 周の数、並べ方(`even`: 均等)、幅の範囲。省略するとラグなし |
| `<profile points>` | ラグの断面の 4 隅(`u h` の組。`u` はベルトに沿う向き、`h` はベルト面から外向き)。`u = 0` に対称な台形 |
| `<ramp from inner_height>` | ラグの上面を内側へ下げる(省略可)。中心面からの距離 `from` から内端まで、直線で `inner_height` に下がる。断面が長方形のときだけ |
| `<track>` の中の `<drive max_torque>` | そのクローラだけを回すモーター |
| `<track>` の中の `<surface>` | そのベルトの接触の性質(下の `<surface>` と同じ属性、`link` なし) |
| `<drive name max_torque tracks>` | 同じ側の複数のクローラを、1 つのモーターで同じ速さで回す。押す力の上限は `max_torque` ÷ ラグ先端の半径。どのクローラも、ちょうど 1 つの駆動で回す |
| `<plate track y inset>` | ベルトと同じ輪郭の動かない板。車体の中央やベルトの間を埋める。`inset` だけ輪郭を縮める |
| `<servo joint gain>` | 関節の位置サーボ。目標の速さを `gain × 角度の誤差` とし、`<limit>` の速さと力で制限する。関節ごとに 1 つ |
| `<surface link friction stiffness damping>` | 車体(根のリンク)の接触の性質。摩擦(省略で地形の摩擦)、剛性 [N/m](省略で 1e5)、減衰 [N·s/m](省略で 1500) |

フリッパーを付けるには、フリッパーのリンク(`<inertial>`)、車体からの回転関節(前は `axis="0 -1 0"`、後ろは `axis="0 1 0"` にすると、正の角度で先端が上がる)、`<servo>` を書き、`<track link="フリッパーのリンク">` でベルトを載せて `<drive>` で回す。

## 速さの目安

ふつうのノートパソコンで、サンプルのコースを 1 台で走らせると実時間の約 4 倍、`World` で何台も同時に動かすと、合わせてその数倍の速さになります。
